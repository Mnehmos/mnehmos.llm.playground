## Operating protocol for subsequent checkpoints
1. Register experiments before execution: hypotheses, actual parent identities, splits, seeds, intervention and budget rules, acceptance/abstention thresholds, controls and stopping criteria. Keep exploratory changes separate and register follow-ups before running them.
2. Preserve actual parent checkpoints and optimizer states. Verify content hashes; never present reconstructed states as historical originals. Missing parents block lineage-specific claims.
3. Separate researcher-supplied structure, observation-derived hypotheses, learned representations and native execution. Record independent ordinary/compositional holdouts, causal dependencies, per-seed outcomes and negative controls; use sealed examinations only for evaluation, never developmental selection.
4. Charge actual observation, matrix construction, decomposition, repair, verification, and rejected proposal costs. Distinguish elapsed/CPU time, approximate operations and actual FLOPs.
5. Continue productive registered branches within available execution budget; retain failures and explicitly state stopping reason.
6. Maintain one canonical Library copy of each artifact, compact optimizer-bearing checkpoint deltas, hashes and historical references. Prioritize executable source, protocols, measurement tables and training-only handoffs. Do not publish sealed labels.
7. Open an unmerged research checkpoint PR for each substantive completed investigation. Promotion requires coordinator review.

This operating protocol is recorded retrospectively here for future studies; it does not retroactively certify older experiments as preregistered.
