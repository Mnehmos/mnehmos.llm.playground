# Continuous scientific auditing after PR #26

This branch starts at PR #26 head b3cc646. Doc 31 found that the Issue #25 student rarely learned the new tasks. Its adaptive comparison used one matched pair and the measurable differences could reflect development-set selection and training noise. This feasibility run uses a new random initialization, seed 409327, and two intervals of the original mixed-task lesson. Its purpose is to verify the instruments and scientific gate. It gives an early trajectory for the same student and task generator.

## What is preserved and reviewed

`sci.loop` starts at step zero and advances by exactly 100 optimizer updates after an explicit, evidence-linked supervisor review. It binds each review to the checkpoint manifest, validates references, requires all thirteen assessments, and checks the observed outcome of the prior prediction. Fixed-arm curriculum proposals are rejected. Diagnostic and weight proposals suspend training until resolved. This implementation has an observation-only weight policy and no persistent edit executor. A curriculum decision must pass the existing lesson validator.

Snapshots are transactionally published to new paths. The manifest covers model, optimizer moments, Torch and data RNG, the learning-rate schedule's phase and cursor, versioned vocabulary and source, the actual lesson, raw trace tensors and interval records. File mode and hash checks protect against accidental replacement. The workspace owner remains able to alter files. Each intervening step records the batch digest, token and family counts, objective losses, learning rates, raw gradient norms, actual AdamW displacement, gradient/update cosines and Adam moment norms for all parameter tensors.

The checkpoint panel retains signed gradients for individual examples, token occurrences and the layers and parameter tensors that receive those signals. Summing occurrence gradients by token ID is checked against the shared embedding gradient. Objective comparisons are unweighted gradient comparisons on a deterministic training-only panel. They reflect local sensitivity. The checkpoint summaries also include all-tensor weight deltas, spectral concentration, activation activity, attention signatures, controlled development probes and comparisons of the mass-block intervention against a comparison site, an unpatched run and a wrong-variable outcome. Match margins and a two-checkpoint streak temper attention-identity and block-status claims. They track a declared block and head signatures. Discovering and tracking arbitrary new subspaces or neuron ensembles is an open extension.

The dynamic Toolsmith takes copies of evidence and safetensors into a fresh filesystem view. It has read-only input mounts, user and PID namespaces, syscall filtering and process limits. It has no mount for the repository, checkpoints outside the chosen snapshot, sealed evaluation or live models. Its runtime currently exposes the system Python standard library. A generated instrument must declare controls and pass them in its own process. This layer records source and runtime and verifies the checkpoint afterwards. The smoke instrument was written in response to the observed concentration on the query token. Its query-excluded cosine was checked with positive and negative controls. Running the actual instrument also checked denied socket creation and denied writes to staged evidence.

The linked evidence bundle contains three distinct reviews authored after inspecting the respective measurements, 200 per-step records, three full snapshots, signed traces and Toolsmith evidence. The two within-budget predictions were confirmed. The last prediction is pending an extension. At 200 updates, familiar-frame sense reached 63.54% on new contexts while new-frame sense reached 0%. Familiar force reached 19.53%. Held-out conversion was 0%. A declared mass-block swap gave the intended answer on 10/77 selected trials and the wrong-variable answer on 9/77. This run verifies the observation workflow and leaves student learnability open.

The first checkpoint build caught shared tensor storage in the trace exporter. The exporter now separates those tensors before safetensors serialization. The submitted feasibility run began at a new empty path. Exact replay verifies the same full first interval, parameter values, Adam history, Torch and data RNG and batch fingerprints. No previous experiment was edited.

## Running the audit

From `research/nri`, use `python -m sci.loop init RUN --seed 409327 --budget 200 --arm toolsmith`. The supervisor reads the newest evidence and trace files and writes a JSON review satisfying the rubric in `sci.loop`. Use `python -m sci.loop review RUN --review FILE` and `python -m sci.loop advance RUN`. The final checkpoint requires a review and passes `python -m sci.loop verify RUN`. Use `python -m sci.tool CHECKPOINT INSTRUMENT_DIRECTORY` for a registered tool run and `python verify_scientific_audit.py RUN` for the smoke replay verification. The evidence bundle includes example reviews and the tool source. Source hashes include the training and audit modules. For exact replay use the same environment and source bytes.

## Prospective design draft

Before registration, verify learnability with fresh development seeds and a constrained per-task curriculum. Begin with a single training phrasing and one input unit pair per task. Score familiar questions and independent changes to written value, unit and phrasing. Bring complexity back in matched increments and record thresholds per task against balanced and prior-based baselines. A subsequent comparative registration must fix the qualified student, seed list, curriculum baseline, intervention authorizations, exact budget, sealed split commitment, primary endpoint and seed-level analysis in advance. The two-interval audit is below the stage where those choices can be fixed from evidence.

The intended comparison uses matched fixed, adaptive with existing instruments, and adaptive with Toolsmith arms. Per-seed initialization and student update budgets are shared. The fixed schedule is a frozen data-generation policy independent of audit content. Audit time, supervisor work and instrument construction are separate resource ledgers. Use a new examiner-held split for final scoring. Test bounded persistent weight modification in a separate arm once optimizer-aware lookahead, preservation testing and exact rollback have been demonstrated. This draft records the design sequence. It does not authorize or report a confirmatory comparison.
