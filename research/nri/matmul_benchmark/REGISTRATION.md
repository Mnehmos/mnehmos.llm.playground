# Matrix multiplication feasibility benchmark (MM-01)

## Motivation and scope
OpenAI's November 24 lower-bound manuscript establishes a claimed exact asymptotic exponent of 9/4 in formal arithmetic, not a practical training kernel. Its October 2 upper-bound manuscript explicitly does not specify a competitive finite matrix size. An independent finite-construction reproduction reports no usable 9/4 rank certificate. This study must not label Strassen or polynomial packing as the 9/4 algorithm.

## Stage A: finite kernel feasibility
Compare torch.matmul (optimized baseline), one-level rectangular Strassen (seven block products, no padding; even dimensions only), and polynomial-packed FFT (explicit real-valued finite algorithm motivated by polynomial multiplication; NOT the asymptotic 9/4 construction; O(mkn log(mkn)) time and O(mkn) storage for this implementation). No modifications to training code or existing PRs.
Shapes (batch,m,k,n): square (1,32,32,32), (1,64,64,64), (1,256,256,256), (1,1024,1024,1024); NRI linear projections (1,4096,64,192), (1,4096,64,64), (1,512,64,256), (1,512,256,64), (1,512,64,13); batched attention (2048,8,16,8), (2048,8,8,16). These are representative contiguous synthetic shapes, not a trace of actual runtime strides. FFT skip when batch*m*k*n > 2^20, Strassen skip odd dimensions. CPU one thread first; optional CUDA separate results. Float32 primary; float64 reference with same inputs. No tuning of candidate depths or selective omission.
Fixed seed 307. Compare forward product and both input gradients under a fixed upstream gradient against float64 torch.matmul. Relative L2 error <=1e-5 for each output/gradient, all finite. This is a screening gate, not a proof of numerical stability. Three warmups and seven interleaved randomized timed repetitions per eligible method, separately forward and forward+backward, with device synchronization; report raw samples, median, speedup vs native, hardware, versions and skipped cases. Exclude input generation; include packing, allocation and autograd overhead. Report all candidates even if slower. Initial run is exploratory on one machine. No claim of exponent from finite timing.
## Stage B: actual 9/4 construction feasibility
Read the upper-bound construction and any subsequent constructive exposition. Identify explicit finite coefficient arrays or an executable exact decomposition, its block size, rank, preprocessing and temporary storage. Verify all basis-pair products exactly before timing. If no feasible certificate or executable construction is available, record BLOCKED rather than silently substituting another algorithm. Do not run unbounded coefficient search. If a candidate becomes available, register a new comparison with the same shapes and accuracy gates.
## Stage C: conditional training benchmark
Only after a candidate passes Stage A accuracy and achieves at least 1.10x median forward+backward speed on a representative NRI shape, profile the unmodified actual training loop, including attention and optimizer; verify whether the candidate accelerates a significant bottleneck. Register a separate integration test with native vs candidate, matched seeds 304,305,307,310,311, fixed original 6000-step objective, optimizer, data order, batch and architecture; include native-v-native timing noise, timing without diagnostic overhead, checkpointing every 100 steps and separate critical-window measurement. Score familiar and unfamiliar accuracy, causal interchange and edits separately; compare numerical drift against native, never claim bit-identical replay unless checked. Report all seeds. Require owner approval before full training integration. No modifications to PRs 32–34. CPU/GPU speedups are not interchangeable.
